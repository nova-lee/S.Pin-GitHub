# 3D 기준 시안 & 실사 자산 표준

> 공유본 안내: HOGA·GYEOL·MEONGIL은 이 DNA의 작성자가 만든 분야별 기준 시안이다. 시안 링크는 키트의 README에 있고, 작성자가 공유한 경우에만 열린다. 열 수 없으면 이 문서의 레시피·공통 골격·함정 목록으로 직접 만든다 — 그래도 같은 기준이 적용된다.

3D가 들어가는 사이트는 백지에서 시작하지 않는다. 아래 **분야별 기준 시안**(또는 그 레시피)에서 구조와 코드를 가져오고, 브랜드·콘텐츠·자산만 바꾼다. 세 시안은 모두 이 DNA의 토큰과 "모션 & 3D 표준"의 체크리스트로 만들었고, 헤드리스 브라우저에서 장(chapter)별로 렌더해 확인했다.

| 분야 | 기준 시안 | 3D가 설명하는 것 | 테마 |
|---|---|---|---|
| 재무·트레이딩 | **HOGA** | 차트의 세 번째 축: 시간(X)·가격(Y)·호가 잔량(Z) | 다크, accent 앰버 = 내 주문·현재가 |
| 가구·도면 | **GYEOL** | 같은 모델의 네 가지 투영: 도식도 → 설계도 → 배치도 → 공간 | 라이트(종이), accent 코발트 = 치수선 |
| 여행·자연 | **MEONGIL** | 실제 360° 사진 속을 걷는다: 은하수 → 설원 → 사막 → 숲 → 초원 | 다크 패널 + 풀블리드 실사 |

**조합 예시 — 가구 × 겨울 (GYEOL 겨울 거실)**: 가구 시안의 모델·도면 파이프라인에 여행 시안의 실사 파노라마 지면 투영과 눈 결정 입자를 더했다. 두 시안은 합성 패스 하나에서 만난다: 색 패스의 알파 뒤에 파노라마를 깔면 의자 그림자가 실제 눈 위에 떨어지고, 입자를 색 패스 안에서 깊이 판정하면 눈이 가구 뒤로 지나간다. 방 안쪽 입자는 정점 셰이더에서 지운다. 실사 위의 카피는 종이색 패널에 담아, 도면 장에서는 바탕에 녹게 한다.

**조합 예시 — 차트 × 겨울밤 (HOGA 겨울밤 차트)**: 재무 시안에 실제 밤하늘 파노라마와 눈 결정 입자를 더했다. 하늘은 장면 안의 배경 구(BackSide, `renderOrder` 맨 앞, 깊이 판정 없음)로 그리고 시선 방향만으로 사진을 읽는다(하늘은 시차가 없다). 사진의 하늘 부분만 쓰고(사진 속 지면과 장면의 지평선 아래는 canvas로 가라앉힌다), 천구를 기울여 은하수를 주인공 뒤에 둔다. 잔량 히트맵은 알파를 주어 하늘이 비치게 했다. 사진이 찍힌 곳과 시기를 푸터에 적는다.

새 분야(의료, 부동산, 제조 등)는 가장 가까운 시안의 골격을 쓰고, 아래 "분야별 레시피"와 같은 표를 먼저 한 줄 채운 뒤 시작한다.

## 고정 원칙 두 가지

**1. 실제에서 출발한다.** 3D의 재료는 실제 이미지·실물 기반 모델·실제 데이터다. 생성 이미지, 합성 풍경, 가짜 수치로 채우지 않는다.

- 풍경: 실제 360° 사진(HDRI)을 지면과 돔에 투영한다. 별·은하수·눈·사막·숲·풀 모두 실제 사진을 쓴다.
- 제품: 실물 기반 PBR 3D 모델(GLB). 도면·윤곽선은 그 모델에서 실시간으로 뽑는다(그려 넣지 않는다).
- 데이터: 실제 과거 데이터(예: 실제 일봉). 실제 데이터가 없는 부분(호가 잔량 등)은 모델이라고 화면에 밝힌다.
- 입자·질감: 실제 사진에서 만든다(예: 벤틀리의 눈 결정 현미경 사진 → 눈 입자 스프라이트).
- 실제 자산을 구할 수 없으면 코드로 만든 형상을 쓰되 "코드로 생성"이라고 보고한다.

**2. 저작권이 깨끗한 것만 쓴다.** 허용: CC0, 퍼블릭 도메인, CC BY(출처 표기 필수). 불가: 출처 불명, 스톡 워터마크, 타사 제품 사진·로고, 유명 디자인의 복제품. 쓴 자산은 화면(푸터·표 캡션)에 이름·작가·라이선스를 적고, 유명 인물·브랜드·캐릭터는 넣지 않는다.

| 자산 | 출처 | 라이선스 | 받는 법 |
|---|---|---|---|
| 360° 풍경, PBR 텍스처, 3D 모델 | Poly Haven (polyhaven.com) | CC0 | `api.polyhaven.com/assets?t=hdris\|models\|textures` → `/files/<id>` → `/info/<id>`(작가·좌표·촬영일) |
| 눈 결정 사진 | Wilson A. Bentley (Wikimedia Commons) | 퍼블릭 도메인 | `commons.wikimedia.org/wiki/Special:FilePath/<파일명>` |
| 천체 | ESO(CC BY 4.0, "ESO/작가" 표기), NASA(대부분 퍼블릭 도메인) | 표기 확인 | 각 기관 이미지 페이지 |
| 시세 | `@observablehq/sample-datasets`(ISC)의 aapl.csv 등 공개 표본 | 패키지 라이선스 + 원자료 표기 | npm |

## 분야별 레시피

**재무 (HOGA)** — 장: ① 차트가 그려진다 → ② 캔들 해부(OHLC 라벨이 3D 위치를 따라감) → ③ 호가 잔량 릴리프(정면은 히트맵, 돌리면 매수·매도 벽) → ④ 지정가 주문과 체결 → ⑤ 전체.
- 캔들·꼬리·거래량은 `InstancedMesh` 3개(드로우콜 3), 색은 `instanceColor`. 진행은 `count`를 늘려 표현한다.
- 잔량 릴리프는 `ShaderMaterial`: 정점 변위 + `dFdx/dFdy` 면 법선 + 등고선. 배경색 uniform은 역보정한 canvas.
- 블룸 임계값 1.5 — HDR로 밝힌 체결 지점만 번진다. 드로우콜 21~23, 삼각형 약 3만.
- 한국 시장 색 규칙(상승 빨강·하락 파랑)이 기본, 글로벌 규칙으로 전환 가능. 상승·하락색은 상태색이 아니라 `--data-up`·`--data-down` 데이터 토큰이고 ▲▼·부호를 함께 쓴다.
- 실제 데이터 창을 고를 때 이야기(주문가에 닿고 반등)가 실제로 일어난 구간을 찾는다. 투자 권유가 아님을 히어로 캡션과 푸터에 적는다.

**가구 (GYEOL)** — 장: ① 완성품(PBR) → ② 도식도(분해 + 부품 라벨) → ③ 설계도(화각 28°→11°로 원근을 접은 입면 + 실측 치수선) → ④ 배치도(위에서 본 평면 + 통로 치수) → ⑤ 벽이 올라오고 재질이 돌아온다(실물 ↔ 도면 전환).
- 도면 모드는 화면 공간 윤곽선 검출이다: ① 색(MSAA 렌더 타깃) ② `MeshNormalMaterial` + 깊이 ③ 합성 패스에서 깊이 라플라시안 + 법선 차 + 배경 경계로 선을 뽑아 종이색 면 위에 잉크로. 어떤 실물 모델에도 그대로 적용된다.
- 투명 캔버스(`alpha: true`)라 배경은 CSS의 canvas 토큰이 그대로 보인다(역보정 불필요). 종이색은 톤 매핑을 거치지 않게 합성 패스에서 섞는다.
- 치수는 모델의 `Box3`와 광선(`Raycaster`)으로 잰 값을 라벨과 사양표에 쓴다. 라벨 앵커도 광선으로 실제 표면에 박는다.
- 섀도맵 `autoUpdate = false`, 형상이 움직인 프레임에만 `needsUpdate`. 아무것도 변하지 않으면 렌더하지 않는다.
- 모델 5점 합계 1.6MB(Meshopt + WebP 1K). 드로우콜 7~66, 삼각형 최대 19만(방 전체).

**여행 (MEONGIL)** — 장소마다 실제 360° 사진 한 장.
- 지면 투영: 프래그먼트 셰이더에서 픽셀마다 광선을 쏘아 지면(y=0) 또는 돔(반경 30m)에 닿은 점을 구하고, 촬영 지점(높이 1.6m)에서 본 방향으로 사진을 읽는다. 카메라가 걸으면 가까운 땅이 먼 산보다 빨리 지나간다.
- 장소 전환은 방향 기반 노이즈 디졸브. 장소마다 자기 카메라(걷는 거리·고개 돌림)를 따로 갖고, 화면에는 두 장소만 섞는다.
- 파노라마는 데스크톱 6144×3072, 터치·좁은 화면 4096×2048 WebP. `fetch → createImageBitmap`으로 받아 밉맵 없이 올리고, 앞뒤 장소만 메모리에 둔다(나머지는 `dispose` + `close`). 첫 장소의 수신 바이트로 프리로더를 채운다.
- 풀블리드 실사 위의 카피는 불투명 canvas 패널에 담는다(블러·그라데이션 스크림 없이 대비 확보).
- 드로우콜 1~2. 전체 자산 약 23MB(첫 화면은 1.5~4MB) — 3D 예산의 "첫 화면 3MB"를 6K에서는 넘는다. 넘는 이유(실사 해상도)를 보고한다.

## 공통 골격 (DNA 3D CORE)

세 시안의 `<script type="module">` 앞부분에 같은 블록이 들어 있다. 새 프로젝트는 이 블록을 그대로 가져가고(또는 아래 명세대로 작성하고) 장면만 바꾼다.

- `createRenderer` — WebGL2 능력 게이트. 실패하면 `.no-webgl` → 같은 구도의 정지 이미지(`fallback.webp`).
- `bindProgress('#journey', chapters)` — 스크롤 → 진행률 하나(0~1), 장 i는 `i/(n-1)`. reduced-motion이면 장별 스냅. 여정이 화면 밖이면 루프 정지. 페이지 안 앵커는 해시를 바꾸지 않고 스크롤만.
- `place(el, world, camera, alpha)` — HTML 라벨을 3D 앵커에. · `lifecycle(...)` — 숨김·화면 밖 정지, 떠날 때 dispose.
- `report(...)` — `#debug` HUD(fps·calls·tris)와 `window.__dna`. · `token()/tokenColor()` — 3D 색도 CSS 토큰에서 읽는다.
- 페이지 구조: `SiteHeader` → `#journey`(100svh 장 5개) → 불투명 `band`(표·사양·출처) → 푸터(가상 브랜드 고지 + 자산 출처 + 기술 스펙).
- 1024px 미만은 오브젝트 위·카피 아래 구도로 바꾸고 카메라 키프레임도 따로 둔다(`isMobile()`과 CSS 분기를 같은 값으로).

## Claude 아티팩트로 게시할 때

- 여러 파일로 게시한다: `index.html` + `fonts/`(사용 글자만 서브셋한 woff2) + `assets/` + `fallback.webp`. HTML이 5만 자 안팎이라 다음 세션이 그대로 읽을 수 있다.
- **`.glb`는 게시되지 않는다.** 모델은 `export default "<base64>"` JS 모듈로 바꿔 `import('./assets/x.glb.js')` → `GLTFLoader.parseAsync`로 읽는다. Draco·KTX2 디코더는 다른 호스트에서 fetch하므로 쓰지 못한다 → Meshopt(JS 모듈) + WebP.
- 뷰어가 루트의 `data-theme`을 바꾼다. 한 테마로 고정하는 3D 페이지는 `html.theme-dark` 클래스로 토큰을 건다.
- 스크립트는 cdnjs·jsDelivr의 고정 버전만(three 0.169.0, gsap 3.12.5, lenis 1.1.13). 다른 호스트로의 fetch·원격 이미지는 막힌다.

## 만들면서 확인한 함정

- `InstancedMesh.count`를 줄여 진행을 표현하면 첫 프레임의 작은 `count`로 경계 구가 계산돼 나중에 통째로 컬링된다 → 전체 `count`일 때 `computeBoundingSphere()`를 먼저 부른다.
- Meshopt·양자화된 GLB는 노드에 큰 스케일이 걸려 있다. 부품을 월드 단위로 옮기려면 `parent.worldToLocal`로 환산한다.
- "변할 때만 렌더"의 변화 판정은 직전 프레임이 아니라 **마지막으로 그린 상태**와 비교한다.
- 라벨은 캔버스 위·`main` 아래에 둔다(z-index 0). 그래야 여정 아래의 불투명 섹션이 라벨을 덮는다.
- WebGL이 없어도 보여야 하는 값(시세, 치수 표)은 렌더러 게이트 앞에서 만든다.
- 후처리(EffectComposer)를 쓰는 페이지만 배경 역보정이 필요하다. 투명 캔버스나 풀블리드 사진 페이지는 필요 없다.

## 검증 기록 (2026-11-17, 작성자 시안 기준)

헤드리스 Chrome(소프트웨어 WebGL)으로 세 시안 모두: 1440·390 폭은 다섯 장 전부, 1920·1280·768 폭은 0·2·4장을 렌더했다. 가로 스크롤 0, 콘솔 오류 0, reduced-motion 정지 구도, WebGL을 끈 상태의 정지 이미지 폴백을 확인했다. 실기기 fps와 아티팩트 뷰어 안에서의 동작은 측정·확인하지 못했다(헤드리스 수치는 성능으로 보고하지 않는다).
