# 내부 페이지 기준 시안 표준 — 결제 · 결재 후 결제 · 관리자 · 표 · 팝업

> 공유본 안내: 아래 "내부 페이지 시안"은 이 DNA의 작성자가 만든 기준 구현이다. 링크는 키트의 README에 있고, 작성자가 공유한 경우에만 열린다. 열 수 없으면 이 문서의 페이지별 골격과 참고처를 기준으로 직접 만든다.

3D 메인 시안이 있는 브랜드의 내부 페이지는 백지에서 시작하지 않는다. 아래 **내부 페이지 기준 시안**(또는 이 문서의 골격)에서 시작하고, 브랜드의 `data.js`(문구·수치)와 accent만 바꾼다. 세 시안은 같은 키트(`kit/kit.css`, `kit/kit.js`, `kit/viewer3d.js`, `kit/pages/*.js`)를 공유하고, 브랜드 차이는 `data.js` 하나와 테마 토큰에만 있다.

| 분야 | 내부 페이지 시안 | 메인(3D) 기준 | 테마 |
|---|---|---|---|
| 가구 | **GYEOL 내부** | GYEOL | 라이트, accent 코발트 |
| 재무 | **HOGA 내부** | HOGA | 다크, accent 앰버, `--data-up`·`--data-down` |
| 여행 | **MEONGIL 내부** | MEONGIL | 다크, accent 오렌지, danger를 #ff6f6f로 이동 |

각 시안의 첫 화면(`index.html`)이 페이지 목록이고, 모든 페이지 맨 위 주석에 `PAGE`·`REFERENCE`·`DATA`·`BUILD` 줄이 있다. 새로 만들 때도 같은 주석을 남긴다.

## 경험 레이어

| 페이지 | 레이어 | 3D | 모션 |
|---|---|---|---|
| 결제, 결재 후 결제 | Product | 메인 시안의 3D 하나를 요약 패널이나 근거 자료 안에 작게. 변화가 있을 때만 렌더, 화면 밖이면 정지 | 사용자 행동에 대한 답만 |
| 관리자, 테이블 갤러리, 팝업 갤러리 | Utility | 없음(팝업 갤러리의 전체 화면 뷰어만 예외) | `duration-base` 이하 |

3D는 three.js r169(importmap, jsDelivr)로 불러오고, WebGL2가 없거나 실패하면 같은 장면의 정지 이미지를 보여 준다. 줄인 모션에서는 자동 회전을 끈다.

## 페이지별 골격

### 결제(주문서)

참고: Stripe Checkout(늘 보이는 요약, 즉시 검증, 금액이 적힌 결제 버튼), Baymard Institute(한 열 폼, 연락처를 묻는 이유, 닫힌 헤더), Toss Payments 주문서(상품 → 배송 → 할인 → 결제수단 → 약관).

- 7/5 분할. 왼쪽은 번호 붙은 단계의 한 열 폼, 오른쪽은 고정 요약(상품, 수량, 할인 코드, 금액 줄, 합계).
- 헤더는 닫는다: 워드마크와 단계 표시(장바구니 → 주문서 → 완료)만, 다른 내비게이션 없음.
- 검증: 포커스를 떠날 때는 필수·형식 필드만 다시 검사한다. 제출 시 오류 요약을 맨 위에 두고 각 필드로 가는 링크를 단다(GOV.UK). 할인 코드 오류는 다시 입력하면 지운다.
- 결제 버튼에 금액을 적는다("1,680,000원 결제하기"). 결제창은 시뮬레이션이며 카드 번호를 받지 않는다. 성공과 실패를 모두 보여 준다.
- 모바일: 하단에 금액과 버튼이 있는 결제 바를 고정한다.
- 분야 고유 검사는 실제 근거로 만든다: 가구는 3D 모델에서 잰 치수로 현관문 반입 여부, 재무는 결제 주기 전환과 정기결제 동의, 여행은 출발일별 남은 자리·여권 영문 이름 형식·취소 규정 표.

### 결재 후 결제

참고: Ramp Procurement(요청 → 결재선 → 결제, 결재자는 금액·수단을 고치지 못함, 결재 순간에 예산과 단가 비교), 국내 전자결재 결재란(직책 머리 + 서명 칸), Linear(오른쪽 레일에 상태와 행동).

- 문서 머리: 문서 번호, 상태 배지(아이콘 + 단어), 결재란(직책, 이름, 일시, 상태).
- 8/4 분할. 본문은 요청 사유 → 품목 표와 합계 → 결재 근거(예산 사용률, 지난 구매 단가, 규정 점검 목록과 진행률) → 첨부 → 의견. 오른쪽 레일은 결재선 타임라인과 **역할별 행동**.
- 역할: 결재자는 규정 확인 체크 후 승인·반려, 요청자는 회수, 재무는 결제 실행(또는 결제수단 선택 후 결제창). 리뷰용으로 역할 전환 세그먼트를 둔다.
- 반려는 사유가 필수인 대화상자, 회수는 경고 대화상자. 되돌릴 수 없는 행동 뒤에는 실행 취소를 주지 않는다.
- 규정 초과(예: 숙박비)는 사유 확인 체크를 해야 승인 버튼이 열린다.
- 모바일: 하단 행동 바가 레일로 이동시킨다.

### 관리자

참고: Stripe Dashboard(지표 + 차트 하나 + 할 일), Shopify Admin(240px 사이드바, 화면당 주 행동 하나), Linear(⌘K 명령 팔레트).

- 240px 사이드바(운영 / UI 기준 두 묶음)와 상단 바. 검색 버튼이 곧 명령 팔레트(Ctrl/⌘K).
- 지표 4개: 단위는 라벨에("(원)"), 큰 금액은 "1억 8,642만"처럼 줄여 한 줄에. 차트는 하나(선 또는 막대): 십자선 툴팁, 방향키 탐색, 기준선, 아래에 데이터 표를 펼쳐 볼 수 있게.
- 할 일·알림 목록과 최근 주문 표. 같은 수치는 화면마다 같아야 한다(알림의 재고 수 = 표의 재고 수).

### 테이블 갤러리

참고: Carbon Data table(선택 시 나타나는 일괄 작업 바, 정렬된 열에만 정렬 아이콘, 펼침 행은 보조 정보), GOV.UK(모바일 카드형 목록), Airtable(표 ↔ 갤러리).

- 여섯 패턴: 기본(로딩·빈·오류 상태 전환) · 일괄 작업(위험 작업은 확인 대화상자) · 펼침 행 · 인라인 편집(검증 + 저장/되돌리기 바) · 넓은 표(고정 첫 열, 가로 스크롤 상자) · 표 ↔ 갤러리 보기.
- 숫자·금액·날짜 열은 오른쪽 정렬, `tabular-nums`. 행 메뉴는 방향키로 움직인다.
- 모바일: 행을 카드로 쌓고 값마다 열 이름을 붙인다.

### 팝업 갤러리

참고: Apple HIG Modality(모달은 최소로, 경고는 행동이 필요할 때만, 시트는 맥락을 남긴 짧은 작업), WAI-ARIA APG·Radix(포커스 가두기, Esc, 포커스 복귀, 방향키 메뉴), Linear(명령 팔레트).

- 끼어드는 정도 순서의 10단계 사다리: 툴팁 → 팝오버 → 메뉴 → 토스트(실행 취소) → 인라인 경고 → 드로어 → 시트 → 대화상자(폼) → 경고 대화상자 → 전체 화면(3D 뷰어).
- 오버레이는 네이티브 `<dialog>`(`showModal`, Esc, 닫으면 연 버튼으로 포커스 복귀, 배경 스크롤 잠금). 대화상자 폼은 바깥 클릭으로 닫히지 않는다.
- 결제창 성공·실패와 명령 팔레트를 함께 둔다.

## 문구와 데이터

- 문체는 `html[data-voice]`로 키트 전체가 따른다: B2B(가구, 재무)는 합니다체, 여행은 해요체. 조사는 받침에 맞춰 붙인다("이름을", "주소를").
- 실제 자산과 데이터: Poly Haven CC0 모델·360° 사진, 공개 표본의 실제 AAPL 일봉. 가격·주문·사람·회사 이름은 예시이며 각 시안 푸터에 실제와 예시를 나눠 적는다.

## 품질 게이트 — 작성자 시안이 통과한 것

- 18개 화면 × 1920·1440·1280·768·390에서 가로 넘침 0.
- axe 접근성 검사 1440과 390에서 위반 0건.
- 결제, 결재(승인·반려·회수·결제 실행), 인라인 편집, 일괄 작업, 팝업 흐름의 자동 클릭 테스트 통과.
- 아직 확인하지 않은 것: 실제 기기의 3D 프레임 속도, 스크린리더로 직접 듣는 테스트. 새 시안도 이 두 가지를 따로 보고한다.
