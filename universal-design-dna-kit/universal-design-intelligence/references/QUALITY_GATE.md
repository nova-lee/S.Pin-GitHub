# 품질 게이트

디자인 구현이 끝났다고 완료가 아니다. 아래 게이트를 **실제 실행 결과로** 통과해야 완료다. 미흡한 항목은 고치고 다시 검증한다.

## 1. 통과 조건

| 항목 | 통과 조건 |
|---|---|
| Visual Quality | 다섯 질문을 모든 요소가 통과. Anti AI-Slop 위반 0. 실제 콘텐츠·실제 이미지로 렌더한 화면 기준 |
| Design Consistency | 하드코딩 색·간격 0(토큰만). 같은 의미의 요소가 페이지마다 같은 모습 |
| UX | 화면마다 목적·주 행동이 하나로 식별됨. 로딩·빈 상태·오류 상태 설계 완료 |
| Functionality | 기존 기능 회귀 0 — 아래 기능 QA 전 항목 실행 |
| Motion | 이야기에 연결된 모션만. 레이어별 상한 준수. reduced-motion 동작 확인 |
| 3D | 실제 WebGL 장면(또는 정확한 명칭으로 보고). 폴백·dispose·뷰포트 밖 정지 확인 |
| Responsive | 5개 해상도에서 깨짐·잘림·가로 스크롤 0 |
| Accessibility | 대비·포커스·키보드·대체 텍스트·reduced-motion 통과, axe 위반 0 또는 사유 기록 |
| Performance | LCP ≤ 2.5s · CLS ≤ 0.1 · INP ≤ 200ms, 3D·이미지 예산 준수 |
| Maintainability | 토큰·컴포넌트 재사용, 임시 코드·중복 컴포넌트 0, 변경 이유 기록 |

## 2. 시각 QA

1920×1080 · 1440×900 · 1280×800 · 768×1024 · 390×844에서 브라우저로 직접 렌더하고 스크린샷을 남긴다. 가능하면 Before / After를 나란히.

확인: 레이아웃 깨짐 · 콘텐츠 잘림 · 타이포 오류(줄바꿈, 고아 단어, 한글 단어 중간 끊김) · 이미지 비율 · 여백 리듬 · 색 일관성(라이트·다크) · 컴포넌트 상태(hover, focus, disabled, loading, error) · 스크롤 동작 · 애니메이션 자연스러움 · 모바일 UX(엄지 영역, 터치 타깃).

**코드만 읽고 화면의 완성도를 추측하지 않는다.**

## 3. 기능 QA

주요 페이지 이동 · 주요 버튼 동작 · 입력과 폼 검증 · 검색과 필터 · API 연결 · 데이터 저장·조회 · 로그인과 인증 · 오류 처리 · 반응형 동작. 기존 테스트가 있으면 전부 실행하고 결과를 그대로 보고한다.

## 4. 성능 QA

초기 로딩(Lighthouse 모바일) · 이미지 최적화 · JS 번들 크기(변경 전후) · 3D 리소스 크기 · GPU 사용(프레임 드롭) · 불필요한 리렌더 · 메모리 누수(페이지 이동 후 WebGL 컨텍스트·리스너 해제) · 애니메이션 프레임.

## 5. PPTX QA

전 슬라이드를 이미지로 렌더해 확인 · 제목만 읽어 이야기가 되는가 · 글자 넘침(대체 서체 기준) · 모든 요소 편집 가능(이미지화된 텍스트·차트 0) · 수치와 출처 대조 · 마스터·레이아웃 사용.

## 6. No Fake Completion

다음은 보고하지 않는다:

- 구현하지 않은 기능을 구현했다고
- 렌더하지 않은 화면을 검증했다고
- 실행하지 않은 테스트를 통과했다고
- 존재하지 않는 3D 모델을 사용했다고, 가짜 3D를 실제 3D라고
- 동작하지 않는 버튼을 완성했다고

최종 보고에는 **실행한 검증과 그 결과, 실행하지 못한 검증과 그 이유, 미완료 항목**을 각각 분리해 적는다.
