## 작업 절차 (순서를 건너뛰지 않는다)

1. **Discovery** — 코드를 바꾸기 전에 구조·프레임워크·빌드·라우팅·페이지·스타일링 방식·컴포넌트·에셋·3D/애니메이션 라이브러리·API·인증·상태 관리·비즈니스 로직을 파악한다. 가능하면 브라우저로 주요 페이지를 실행해 스크린샷을 남긴다. 코드만 읽고 화면 품질을 추측하지 않는다. 기존 프로젝트면 `PROJECT_AUDIT.md`(구조, 스택, 페이지, 디자인 문제, 제약, 재사용 가능 컴포넌트, 우선순위, 방향, 리스크)를 먼저 쓴다.
2. **Project DNA** — 브랜드·대상·목적·플랫폼·기술 제약을 정리하고, 기본 토큰에서 바꿀 것(accent 계열, 서체, 반경 성격, 밀도)만 정한다. 페이지마다 경험 레이어를 지정한다. 결정은 프로젝트의 `DESIGN.md`에 기록한다. accent를 바꾸면 두 테마 대비(텍스트 4.5:1, 경계·포커스 3:1)를 계산해서 확인한다.
3. **Build** — 순서: 토큰 → 타이포 → 전역 레이아웃 → 헤더/내비 → 푸터 → 공통 컴포넌트 → 랜딩 → 제품/서비스 → 유틸리티 페이지 → 폼/다이얼로그/테이블 → 반응형 → 모션·3D → 접근성 → 성능.
4. **Verify** — `references/QUALITY_GATE.md`를 실제 실행으로 통과한다. 5개 해상도(1920·1440·1280·768·390), 라이트·다크, 키보드·대비·reduced-motion, 기존 기능 회귀, 성능.
5. **Report** — 실행한 검증과 결과 / 실행하지 못한 검증과 이유 / 미완료 항목을 나눠서 보고한다. 기존 프로젝트면 `FINAL_IMPLEMENTATION_REPORT.md`.

기존 프로젝트를 바꿀 때: API 계약·데이터 구조·인증·라우팅·사용자 흐름·비즈니스 로직을 보존한다. 디자인을 이유로 기능을 제거·단순화하지 않는다. 구조 변경은 이유와 영향을 먼저 적는다. 파일 삭제·설정 덮어쓰기 전에 git 브랜치나 백업을 만든다. 새 라이브러리는 호환성·중복·필요성·번들 영향을 확인하고 버전을 고정한다. 라이브러리 API는 추측하지 말고 현재 버전 문서를 확인한다.

## 핵심 규칙 (상세는 references)

- **Design before Decoration.** 모든 요소는 다섯 질문에 답한다: 왜 존재하는가 · 무엇을 전달하는가 · 사용성을 개선하는가 · 브랜드에 기여하는가 · **없어도 완성도가 유지되는가**(예 → 제거 검토).
- 화면마다 목적 하나·주 행동 하나. 위계는 크기 → 굵기 → 여백 → 대비 순, 색은 마지막.
- 잉크와 종이: 바탕 `canvas`(순백 금지), 주 버튼은 `primary`(잉크) 채움. `accent`는 면적 5% 이하로 링크·포커스·켜짐·정보·데이터 강조·브랜드 순간에만.
- 하드코딩 hex·px 금지, 토큰만. 같은 의미는 같은 토큰.
- Anti AI-Slop: 보라·파랑 그라데이션, 모든 섹션 3열 아이콘 카드, glassmorphism·블러, glow·과한 그림자·왼쪽 색 띠, 가짜 3D, 가짜 수치·후기·로고, 전부 중앙 정렬, 모든 섹션 같은 fade-up, 이모지 장식, 저품질 AI·스톡 이미지 — 기본 금지.
- Pretendard Variable 하나로 한글·라틴 조판, `word-break: keep-all`, 본문 행간 1.6~1.7, 숫자 `tabular-nums`. 왼쪽 정렬 기본.
- 3D는 Brand Experience 페이지에만, 보여줘야 이해되는 것이 있을 때만. 실제 이미지·실물 모델·실제 데이터로, 저작권이 깨끗한 자산(CC0·퍼블릭 도메인·CC BY)만. 폴백 없는 3D는 미완성.
- 레퍼런스는 저명한 사이트에서 **구성과 기법**만 가져오고 브랜드·레이아웃·자산은 가져오지 않는다. 무엇을 어디서 가져왔는지 `REFERENCE` 주석에 남긴다.
- No Fake Completion: 하지 않은 구현·렌더·테스트를 했다고 보고하지 않는다. CSS로 흉내 낸 3D는 "CSS 3D 변형", 사전 렌더는 "사전 렌더 시퀀스"라고 정확히 부른다.
